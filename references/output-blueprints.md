# Output Blueprints

Use these only when the learner requests a reusable artifact. A guided session normally stays in conversation.

## Required Core-Node Block

Every core section in a guide, plan, graph companion, or notebook must end with:

```markdown
Learner output: [one observable task]
Advance when: [specific success criterion]
Pause: [return with this evidence before continuing interactively]
```

Do not collect all evidence tasks into one final quiz. Keep answers or hints separate unless an answer key is explicitly requested.

## Study Guide

- observable target capability
- prerequisite-aware core path
- required versus optional content
- common confusions
- required core-node block after each core section
- only the resources and modalities justified by the target

Do not append a generic weekly schedule by default.

## Knowledge Graph

- target capability
- prerequisites and core trunk
- bridge and optional nodes
- common confusions
- checkpoint table: node, learner output, advance criterion

Use Mermaid only when visual structure improves understanding.

## Tutorial Notebook

For each core experiment, use:

1. predict
2. run
3. inspect
4. explain
5. modify or transfer

Then add the required core-node block. Keep cells short, deterministic, and runnable in order. Save or verify key outputs when the notebook is delivered as completed material.

## Diagnostic Artifact

Create a portable quiz, scoring rubric, and answer key only when explicitly requested. Sample concept, relationship, application, and implementation evidence; report gaps by knowledge node rather than relying only on one overall score.

## Learning Plan

- current evidence, not assumed level
- target outcome and constraints
- minimum core path
- required core-node block for each checkpoint
- re-planning rule when evidence exposes a gap

Use dates or week numbers only when they help execution.
